# v3

The decisions of the owner on v3 (2026-11-22); the tracking issue is
[#351](https://github.com/Heiss/nova-imperium/issues/351). **[V]** This
concept stands under Operations because it is a plan of how releases are
built, beside [Branching and release](/ops/branching-release.md).

* **[E]** v3 has no release number (owner, 2026-11-22).
* **[E]** The foundation goes to `main` in normal releases, as refactors
  without a change of behaviour (owner, 2026-11-22). Its issues: #373 (a
  rule for whether a view is offered), #374 (a server feature says whether
  it is enabled for the round), #375 (catalog entries and missions can be
  „not offered“, the Lexicanum included), #376 (a typed layer of modifiers
  for production, times, combat and flight), #377 (due jobs in the clock
  besides the fleets), #378 (the hand-kept lists register themselves),
  #379 (address parameters per view).
* **[E]** All features of v3 are built on a v3 branch and released
  together, as the next large release (owner, 2026-11-22, evening; this
  replaces „each finished feature goes to `main` on its own“ of the
  morning). The first feature is #160, the interactive star map with the
  fog (M2); it needs #373, #379 and the option boxes of #378.
* **[E]** Test features in the admin panel (owner, 2026-11-22): off by
  default; a heading with an explanation; one button with a question, then
  the switches of the alpha and beta features; a switch whose dependency is
  off is greyed out with the reason; a finished feature moves to the normal
  list of settings.
* **[E]** The release notes name the features that are integrated but
  still in test (owner, 2026-11-22).
* **[U]** Open, as on #351: the name of the v3 branch, the image for the
  test server, the CI on that branch, and how often `main` is merged into
  it; the rules of the fog (M2 of #160), which is built on the v3 branch
  because the analysis found no clean place for it on `main`.

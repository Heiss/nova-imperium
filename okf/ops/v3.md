# v3

The decisions of the owner on v3 (2026-11-22). Their source is the
tracking issue [#351](https://github.com/Heiss/nova-imperium/issues/351):
its description („What v3 is“, „Requirement for everything new in v3“,
„Test features in the admin panel“, the sentence on the release notes) and,
for the shape of the release and the foundation, its comment of the
evening of 2026-11-22. **[V]** This concept stands under Operations
because it is a plan of how releases are built, beside
[Branching and release](/ops/branching-release.md).

* **[E]** v3 has no release number: a number would fix it to one release
  (owner, 2026-11-22, #351).
* **[E]** v3 is developed apart from the bug-fix releases, which go on from
  `main` as before; bug fixes of the releases are merged back into the v3
  branch. The owner tests v3 on a separate test server with the candidate
  image of its pull request (owner, 2026-11-22, #351).
* **[E]** The foundation goes to `main` in normal releases, as refactors
  without a change of behaviour (owner, 2026-11-22, #351). Its issues:
  #373 (a rule for whether a view is offered), #374 (a server feature says
  whether it is enabled for the round), #375 (catalog entries and missions
  can be „not offered“, the Lexicanum included), #376 (a typed layer of
  modifiers for production, times, combat and flight), #377 (due jobs in
  the clock besides the fleets), #378 (the hand-kept lists register
  themselves), #379 (address parameters per view).
* **[E]** All features of v3 are built on a v3 branch and released
  together, as the next large release (owner, 2026-11-22, evening, #351;
  this replaces „each finished feature goes to `main` on its own“ of the
  morning). The first feature is #160, the interactive star map with the
  fog (M2); it needs #373, #379 and the option boxes of #378.
* **[E]** Everything new in v3 can be switched off in general by the
  admin, so that nothing is activated by accident in the running round
  (owner, 2026-11-22, #351).
* **[E]** Test features in the admin panel (owner, 2026-11-22, #351):
  * the star map (#160) can be switched on in general, not per player; the
    default is off; it ships as „release alpha“ and is shown as such;
  * a new heading for the test features, with an explanation;
  * under it one button; it opens a dialog that asks whether the test
    features should really be activated, and only after a yes do the
    switches of all alpha and beta features appear;
  * the test features named so far are alpha: the star map (#160), the
    ground combat (#155, the owner's „Landangriffe“) and the building on
    fields (#158, the owner's „Felderbau als Stellaris“); every test
    feature has a switch of its own; a feature that depends on another can
    be switched on only while that one is on, before that its switch is
    greyed out with the reason;
  * a finished feature moves its switch into the existing list of
    settings;
  * purpose: the owner tests such a feature on a separate server.
* **[E]** The release notes name every feature that is integrated but
  still in test, so the players know that something new is coming
  (owner, 2026-11-22, #351).
* **[U]** Open, as on #351: the name of the v3 branch; how the candidate
  image of the v3 pull request is built (today only a head `release/*`
  gets one); which CI runs on the v3 branch and when; how often `main` is
  merged into it; which small items stay in a normal release; the rules of
  the fog (M2 of #160), which is built on the v3 branch because the
  analysis found no clean place for it on `main`.
* **[U]** Open for the test features, as on #351: the German texts (the
  heading, the explanation, the question, the marks „Alpha“ and „Beta“);
  which further items are test features, and whether one may start as
  beta; whether a switch applies to the server or to a round
  and what happens to a running round; whether the yes of the dialog is
  remembered and written to the audit log; whether the players see the
  mark; whether pure interface changes (#348, #349, #356) fall under it.

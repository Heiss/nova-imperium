#317 and #118, without a change of the game, of a text, of a value, of an action name or of the JSON on the wire: the boundary between the browser and the server is checked by the compiler (owner, 2026-11-20, „jetzt komplett“). The input of every action is declared once, per feature, in `src/core/actions/` (59 actions in 21 files; the list is generated, `scripts/gen-features.ts`, and `ActionMap` merges it); every server handler is a `Handler<'name'>` and the tables `actions`, `guildActions` and `adminActions` of a feature are checked against the map, so a wrong name or a handler of another input does not compile, and `action-contract.test.ts` checks that the registered names are exactly the declared ones. `act`, `actHere` and `quiet` take the name and the data of that name (`ActionArgs`); the call sites, the archive reads that went through `ctx.api` and the transport in `logic/act.ts` follow. The state is typed too: `src/core/state/<part>.ts` declare the shape of each part (12 files, the frame and 11 features), the server checks what each part builds against it (`StatePart<StateShape>`, `keyed`, `lockedState`), and `GameState` is derived from the generated list instead of written by hand; `state-contract.test.ts` checks that every key has a shape and every shape a sender. [V] The compiler found no wrong call site. It found two places where the hand-written type differed from what the server sends: `GuildChatMessage.arrival` can be `null` (the column is nullable; the browser would have shown 1970 for an attack row without a time, `logic/guilds.ts` now treats `null` like a missing time), and `AdminState.specs` is `readonly`. Server-side validation stays as it is; types do not replace it.

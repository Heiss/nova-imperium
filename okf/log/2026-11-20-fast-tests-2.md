The unit suite is faster again, because every test also runs for every static mutant of the complete mutation run (#304). No test case was removed, no assertion weakened, no `numRuns` lowered and no game code changed; the time comes from cheaper set-up. `testCtx()` keeps the prepared statements of its database by their SQL text (`src/test/statement-cache.ts`; the code under test prepares per call, which was about half of the time of a route test; a call that changes a statement, `pluck()` and the like, gets a statement of its own); the password hash of `addUser` is written out in `src/server/test-helpers.ts` instead of computed with scrypt in every test file, and `src/server/test-helpers.test.ts` fails when the scrypt profile changes. A property test that builds a world per generated case (`missions-reference`, `research-reference`, the chat limit of `guild-chat`) takes one migrated database and rewinds it after each case (`caseDatabase()`). The migration property tests reuse one rewound database per version, no longer snapshot every table where only the integrity check is read (`checkUpgrade`), and the upgrade test with backups builds the old database from the kept migrated one. `journal-cost.test.ts` turns the statement cache off, because it measures what the server costs per action and arrival. The route and passkey tests that only need the login to answer memoise scrypt like the earlier ones. Left as they are, because the time is the work itself: `settle-reference`, `producer-rows` and the other reference tests that compute, `ci-release` (a shell and Node process per case) and the measurement of `journal-cost`.

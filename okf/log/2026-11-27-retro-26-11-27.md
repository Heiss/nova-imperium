Retrospective of the release 26.11.27, the security hotfix tagged on 2026-11-25 at 14:12 UTC on `hotfix/sec-6e57d81287` ([Release loop](/ops/loop.md)). Its cause was #397, the Trivy finding HIGH CVE-2026-124851 in `libzstd1` of the base image of 26.11.25. The fix #398 went into the hotfix branch by auto-merge with one CI run of 30 minutes, the release pull request #399 (Release 26.11.27) with one run of 34 minutes; from the issue to the tag took 1 h 16 min, from the issue to the fix in `main` 5 h 29 min. What cost time: the automatic merge-back #402 could neither be brought up to date (the ruleset of `hotfix/**`) nor merged (`main` needs an up-to-date and linear history), and was replaced by hand with #403; until then the release pull request #393 failed with „Released hotfix not in main yet“. The first push run of the hotfix branch ran the complete mutation run, 134 minutes, shard 5 alone 133. The release run had no Trivy job, because its workflow came from the tree of 26.11.25. 26.11.26 was held by the old release pull request, so 26.11.28 became the next release. Consequences, all decided before: #413 (the merge-back as `hotfix-back/<name>`, built by `tag.yml`; owner, 111a, 116a, 118a), the guard that never releases at or below the newest tag (owner, 108 and 108a, [Never retroactive](/log/2026-11-25-never-retroactive.md)), and #371 (the static mutants, open). No new consequence.

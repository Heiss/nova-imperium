#226, #222. Private messages between players ([Private messages](/features/private-messages.md)): conversations of two players in the view „Nachrichten“ with the tabs „Berichte“, „Posteingang“ and „Gesendet“, text of up to 1,000 characters, a rate limit of one message every 2 seconds per sender (as the guild chat, #169; above it the limit of #328), the last 500 messages per conversation, deleted by a new round, deleting from one's own view, a block list and the switch „only friends may write to me“ (the buddy list, #227) with one neutral refusal for both, the push kind `private-messages` without the text (#192), „Melden“ on a received message and the admin tab „Gemeldete Nachrichten“ with an audit entry per opening, and the sender „Gelöschter Spieler“ for a deleted account (the pseudonym of the round archive, #235). Decided by the owner on 2026-11-21 (Q22 to Q25 included); the wording of the refusal text is [V]. New: migration `20261121T1000-private-messages`, the repository `privateMessages`, the server module `src/server/game/private-messages.ts`, the client feature `private-messages`. The vacation mode lets the actions through. Changelog fragment `changes/private-nachrichten.md` as a draft.

Third step, Q32 to Q35 [V] (coordinator, 2026-11-21; [Private messages](/features/private-messages.md)): the state carries only the newest message of each conversation as the preview, with the unread count and `more` (the poll of 20 conversations of 500 messages of 1,000 characters is 27,356 bytes; it was 10,587,750 with the whole history and 1,064,698 with a page of 50). A conversation loads its newest 50 by the action `openPrivateConversation` when the player opens it, older pages by `olderPrivateMessages`; the tab „Gesendet“ loads its newest 50 sent messages by `sentPrivateMessages` when it is opened, with „Ältere Nachrichten laden“ for older ones. Both loads check the player's own messages only (a foreign, odd or unknown id answers „Diese Nachricht gibt es nicht.“ and stores nothing, hidden messages are left out) and work on the lock screen (Q34: „Melden“, „Löschen“ and „Blockieren“ stay there). The browser names the open conversation and the newest message it holds in the poll (`GET /api/state?pm=&pmAfter=`) and in the body of every action; the state then carries the newer messages of that conversation as `privateMessages.open`. No load is sent without a click, never by a redraw of the poll (#335): the class `click` of the three loads in `src/core/action-kind.ts` is for the main agent (the file is not on the branch). Journal allow-list entries for the two new actions; the message text stays out of the journal, the audit log, a push and a log line, and the marker test covers the new actions.

At the merge with #335 (main agent, 2026-11-21; [Own activity](/features/own-activity.md)): the eleven new actions have their classes in `ACTION_KIND`. **click**: `openPrivateConversation`, `olderPrivateMessages`, `sentPrivateMessages`; **auto** [V]: `readPrivateMessages`, sent by the page itself after a moment, as `read`; **change**: `sendPrivateMessage`, `deletePrivateMessage`, `deletePrivateConversation`, `reportPrivateMessage`, `blockPlayer`, `unblockPlayer`, `privateMessageOptions`.

At the merge (main agent, 2026-11-21): the tab read „Posteingang(1)“, because Svelte drops the whitespace at the start of an `{#if}` block; the label is now one string, „Posteingang (1)“. Tests added for the late refusal, the missing admin and the admin change of the reported messages, and for a newest message without a name in the state URL.
